### 核心理念
生成的代码应该是**完整的端到端解决方案**：
- ✅ 接收已加载的数据（通过 `data` 字典）
- ✅ 处理和转换数据为模型可用格式
- ✅ 构建和求解优化模型
- ✅ 输出可理解的结果
- ✅ 可以直接运行，无需修改

### 数据传递方式

**重要**：数据已经在内存中加载，通过 `data` 字典传递给模型构建函数：

```python
# main.py 中的数据加载（已完成）
data_loader = DataLoader()
data_loader.connect()
data = data_loader.load_all(version_id)  # 加载所有表数据和路径数据

# data 包含表数据和路径数据
# data["tables"] - 所有表数据
# data["paths"] - 路径数据

# 调用模型构建函数
model = build_model(data)  # data 包含所有表数据和路径数据
```

**data 字典结构**：
```python
data = {
    # 表数据（嵌套在 "tables" 键下）
    "tables": {
        "resource": pd.DataFrame(...),      # 资源表
        "demand": pd.DataFrame(...),        # 需求表
        "transport": pd.DataFrame(...),     # 运输表
        ...                                 # 其他业务表
    },

    # 路径数据（List[List[str]] 格式）
    "paths": [
        ["source_001", "source_001_node_A", "node_A", "node_A_demand_001", "demand_001"],
        ["source_002", "source_002_node_B", "node_B", "node_B_demand_002", "demand_002"],
        ...
    ]
}
```

**路径序列格式说明**：
- 每个路径是一个字符串列表，节点和边交替排列
- 格式：`[node1, edge1, node2, edge2, ..., nodeN]`
- 第一个元素是起点（资源节点），最后一个元素是终点（需求节点）
- 奇数位置（0, 2, 4, ...）是节点，偶数位置（1, 3, 5, ...）是边

### 输出要求

#### 1. 代码结构（3个核心函数）

**build_model(data)**：
- **输入**: `data` 字典（包含所有表数据和路径数据）
- **处理**:
  1. 从 `data["tables"]` 字典中使用table_name提取表数据（DataFrame 格式）
  2. 从 `data["paths"]` 提取路径数据（List[List[str]] 格式）
  3. 转换数据为模型可用格式（集合、参数）
  4. 使用 Pyomo 构建优化模型
- **输出**: Pyomo ConcreteModel 实例
- 示例：
  ```python
  def build_model(data):
      """构建优化模型

      Args:
          data: 包含所有数据的字典
              - 表数据: data["tables"]["table_name"] (pd.DataFrame)
              - 路径数据: data["paths"] (List[List[str]])

      Returns:
          Pyomo ConcreteModel 实例
      """
      from pyomo.environ import (
          ConcreteModel, Var, Objective, Constraint,
          NonNegativeReals, maximize, minimize
      )

      # 1. 提取表数据
      tables = data["tables"]
      resources_df = tables["resource"]
      demands_df = tables["demand"]
      transport_df = tables["transport"]

      # 2. 构建集合和参数
      # 直接从表数据提取ID集合（用于约束条件）
      RESOURCE_IDS = set(resources_df['resource_id'])
      DEMAND_IDS = set(demands_df['demand_id'])
      TRANSPORT_IDS_SET = set(transport_df['edge_id'])

      PARAM_RESOURCE_CAPACITY = dict(zip(
          resources_df['resource_id'],
          resources_df['capacity']
      ))

      PARAM_DEMAND = dict(zip(
          demands_df['demand_id'],
          demands_df['demand_quantity']
      ))

      # 构建边单价字典
      PARAM_EDGE_PRICE = {}
      for _, row in transport_df.iterrows():
          edge_id = row['edge_id']
          PARAM_EDGE_PRICE[edge_id] = float(row['unit_price'])

      # 3. 提取路径数据
      paths = data["paths"]

      # 将路径列表转换为元组，用作 Pyomo 变量索引
      # Pyomo 要求索引必须是可哈希的（hashable），列表不可哈希，需要转换为元组
      FEASIBLE_PATHS = [tuple(path) for path in paths]

      # 4. 创建 Pyomo 模型
      model = ConcreteModel(name="optimization_model")

      # 5. 定义决策变量
      # 使用路径元组作为索引（而不是顺序索引）
      model.VAR_PATH_FLOW = Var(
          FEASIBLE_PATHS,
          domain=NonNegativeReals,
          doc="Flow on each path"
      )

      # 6. 定义目标函数
      def calculate_objective():
          # 基于路径的目标函数
          total_cost = 0
          for path_seq in FEASIBLE_PATHS:
              # 遍历路径中所有元素，通过集合成员判断筛选出边
              path_price = sum(
                  PARAM_EDGE_PRICE.get(e, 0)
                  for e in path_seq
                  if e in TRANSPORT_IDS_SET
              )
              # 计算路径成本（单价 × 流量）
              total_cost += path_price * model.VAR_PATH_FLOW[path_seq]
          return total_cost

      model.objective = Objective(
          expr=calculate_objective(),
          sense=minimize
      )

      # 7. 定义约束条件
      # 需求满足约束
      def demand_satisfaction_rule(model, d):
          return sum(
              model.VAR_PATH_FLOW[path_seq]
              for path_seq in FEASIBLE_PATHS
              if path_seq[-1] == d  # 路径的最后一个元素是需求节点
          ) == PARAM_DEMAND[d]

      model.demand_satisfaction = Constraint(
          DEMAND_IDS,
          rule=demand_satisfaction_rule
      )

      # 资源容量约束
      def resource_capacity_rule(model, r):
          return sum(
              model.VAR_PATH_FLOW[path_seq]
              for path_seq in FEASIBLE_PATHS
              if path_seq[0] == r  # 路径的第一个元素是资源节点
          ) <= PARAM_RESOURCE_CAPACITY[r]

      model.resource_capacity = Constraint(
          RESOURCE_IDS,
          rule=resource_capacity_rule
      )

      return model
  ```

**solve_model(model)**：
- **输入**: Pyomo ConcreteModel 实例
- **处理**:
  1. 从 DSL 中获取求解器配置
  2. 使用 SolverFactory 创建求解器
  3. 配置求解器参数（timeout, gap, threads等）
  4. 执行求解
- **输出**: 求解结果对象
- 示例：
  ```python
  def solve_model(model):
      """求解优化模型

      Args:
          model: Pyomo ConcreteModel 实例

      Returns:
          求解结果对象
      """
      from pyomo.opt import SolverFactory

      # 创建求解器
      solver = SolverFactory('scip')

      # 配置求解器参数
      solver.options['limits/time'] = 300  # 5分钟超时
      solver.options['limits/gap'] = 0.01  # 1% gap

      # 求解
      results = solver.solve(model, tee=True)

      # 将 model 附加到 results 对象，供 parse_result 使用
      results.model = model

      elif results.solver.termination_condition == TerminationCondition.feasible:
          print("找到可行解")
      else:
          print(f"求解失败: {results.solver.termination_condition}")

      return results
  ```

- **输入**: 求解结果对象、原始数据和输出目录路径
- **处理**:
  1. 提取所有决策变量的值
  2. 提取目标函数值
  3. 将每个决策变量输出为Excel的一个sheet
  4. 将目标函数输出为Excel的一个sheet
  5. 计算关键指标（总成本、总流量等）
  6. 格式化输出结果字典
- **输出**: 结果字典（同时生成Excel文件）
- **Excel输出要求**:
  - 文件名: `decision_variables.xlsx`
  - 每个决策变量一个sheet，sheet名称为变量名（如 "VAR_PATH_FLOW"）
  - 目标函数单独一个sheet，名称为 "Objective"
  - 每个sheet包含变量的索引和对应的值
  - **重要**：输出所有决策变量，不做任何过滤（包括 None 值和 0 值都要输出）

#### 2. 关键注意事项

**数据访问**：
- ✅ 使用 `data["tables"]["table_name"]` 访问表数据（DataFrame）
- ✅ 使用 `data["paths"]` 访问路径数据（List[List[str]]）
- ❌ 不要使用 `pd.read_csv()` 或其他文件读取函数
- ❌ 不要使用 `json.load()` 读取路径文件

**路径数据处理**：
- 路径数据是 List[List[str]] 格式，每个路径是节点和边的交替序列
- 路径格式：`[node1, edge1, node2, edge2, ..., nodeN]`
- **提取节点**：
  - 资源节点：`path_seq[0]` （第一个元素）
  - 需求节点：`path_seq[-1]` （最后一个元素）
- **提取边**：
  - **禁止使用数值索引**（如 `path_seq[1::2]`）
  - **必须使用集合成员判断**：`e in TRANSPORT_IDS_SET`
  - 直接从表数据提取时转换为集合：`TRANSPORT_IDS_SET = set(transport_df['edge_id'])`
  - 遍历路径筛选边：`[e for e in path_seq if e in TRANSPORT_IDS_SET]`
- 将路径列表转换为元组：`[tuple(path) for path in paths]`
- 使用路径元组作为 Pyomo 变量索引（而不是顺序索引）

**边单价处理**：
- 从运输表（transport_df）中提取边单价和边ID集合
- 构建 `PARAM_EDGE_PRICE` 字典：`{edge_id: unit_price}`
- **重要**：直接从表数据提取ID时就转换为集合，提高查找效率
- 在目标函数中动态计算：
  ```python
  # 直接从表数据提取边ID集合（在数据加载阶段完成）
  TRANSPORT_IDS_SET = set(transport_df['edge_id'])

  # 遍历路径中所有元素，通过集合成员判断筛选出边
  path_price = sum(
      PARAM_EDGE_PRICE.get(e, 0)
      for e in path_seq
      if e in TRANSPORT_IDS_SET
  )
  # 计算总成本（单价 × 流量）
  total_cost += path_price * flow
  ```

  **注意**：
  - **禁止使用数值索引**（如 `path_seq[1::2]`）来提取边，除非是提取资源节点（`path_seq[0]`）或需求节点（`path_seq[-1]`）
  - 必须使用 `e in TRANSPORT_IDS_SET` 来判断元素是否为边
  - 所有ID集合（RESOURCE_IDS、DEMAND_IDS、TRANSPORT_IDS_SET）都应在提取时直接转换为set

**模型构建**：
- 使用 Pyomo 的 ConcreteModel
- 决策变量使用整数索引（`range(len(paths))`）
- 约束条件中使用 `enumerate()` 遍历路径
- 目标函数中动态计算路径成本
