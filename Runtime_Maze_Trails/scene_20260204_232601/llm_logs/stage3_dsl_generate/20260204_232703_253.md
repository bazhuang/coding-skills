### 核心理念
DSL是**代码生成的模板**，不是数据容器：
- ✅ 定义如何读取路径数据（数据源、字段映射）
- ✅ 定义路径集合的概念（路径是什么格式）
- ✅ 定义基于路径的决策变量（如何索引）
- ❌ 不包含具体的路径实例数据

### 输出要求

#### 0. data_def.tables（数据表定义）

**表选择原则**：

DSL的 `data_def.tables` 应包含**参与优化计算的表**，遵循以下规则：

1. **必须保留的表**：
   - 核心业务表（table_type为 demand, resource, transport）
   - 在 business_constraints 中被引用的表
   - 有约束字段的节点表（如 capacity, upper_bound, lower_bound）

2. **可以过滤的表**：
   - 关系表（table_type为 link）：在基于路径的建模中，路径数据已包含拓扑关系
   - 无约束的透传节点表：只有ID和名称，不参与优化计算
   - 纯元数据表：只包含 gmt_create, gmt_modified, creator 等字段

3. **字段精简**：
   - 每张表只保留参与优化的字段
   - 过滤掉纯元数据字段（gmt_create, gmt_modified, creator, modifier）
   - 保留主键、外键和业务字段

#### 1. data_def.index_sets（集合索引定义）

**从业务表提取的集合**：
- 从tables字段提取所有离散集合（如ORDER_IDS, VEHICLE_IDS, LOCATION_IDS）
- source_table和source_field指向业务表
- 示例：
  ```json
  {
    "set_name": "ORDER_IDS",
    "description": "订单ID集合",
    "source_table": "orders",
    "source_field": "order_id"
  }
  ```

**路径集合定义**：
- **集合名称**：FEASIBLE_PATHS
- **source_table**：指向路径数据来源（如 "paths_data"）
- **source_field**：指向路径列表字段（如 "paths"）
- **数据格式说明**：在description中说明路径格式
- 示例：
  ```json
  {
    "set_name": "FEASIBLE_PATHS",
    "description": "可达路径集合，每个元素是[节点ID,边ID,节点ID,...,边ID,节点ID]的列表",
    "source_table": "paths_data",
    "source_field": "paths"
  }
  ```
- **关键点**：
  * 不在DSL中列出具体路径
  * 只说明数据来源和格式
  * 路径本身作为索引键

#### 2. data_def.parameters（参数定义）

**业务参数**：
- 映射业务表的数值字段
- param_name前缀为PARAM_
- 示例：PARAM_VEHICLE_CAPACITY, PARAM_DEMAND, PARAM_RESOURCE_CAPACITY

**参数示例**：
- **运力/边成本参数**
  - source: 运力供给表的成本相关字段（如 `agent_ads_transport_d.transport_price`）
  - index_sets: id类的索引参考primary_key
  - 用途：在目标函数中用于计算路径相关成本
  - 示例：
    ```json
    {
      "param_name": "PARAM_TRANSPORT_PRICE",
      "source": "agent_ads_transport_d.transport_price",
      "index_sets": ["TRANSPORT_IDS"],
      "data_type": "float",
      "desc": "运力价格信息"
    }
    ```

**注意**：
- ⚠️ 价格类型：固定单价、阶梯价、分段计价等多种形式，对于非固定单价，DSL 只需定义数据来源
- 价格类参数
  - `desc`字段除了基础描述，价格类参数还必须明确具体的价格类型
  - `data_type`字段
    - "float": 固定单价
    - "str" or "json": 阶梯价、分段计价

#### 3. decision_vars（决策变量定义）

**路径决策变量（必须）**：
- 当有路径数据时，必须定义基于路径的决策变量
- 索引为FEASIBLE_PATHS
- 变量值的含义与路径相关
- 示例：
  ```json
  {
    "var_name": "VAR_PATH_FLOW",
    "description": "路径flow，索引为完整路径列表[node,edge,node,...]",
    "var_type": "continuous",
    "index_sets": ["FEASIBLE_PATHS"],
    "lower_bound": 0
  }
  ```

**其他决策变量**：
- 根据业务逻辑定义
- 可能与路径变量配合使用

#### 4. objective（目标函数）

**目标函数子项化表达**：
- 目标函数通过 `obj_terms` 数组表达，每个子项代表一个成本/收益组成部分
- 最终目标函数 = 所有子项的加权和
- 每个子项包含：
  * `term_name`: 子项名称（如 TERM_TRANSPORTATION_COST）
  * `expression`: 子项的数学表达式（如 `sum(PARAM_PATH_PRICE[p] * VAR_PATH_FLOW[p] for p in FEASIBLE_PATHS)`）
  * `coefficient`: 子项系数（默认1，可用于加权）
  * `desc`: 子项业务含义

**示例**：
```json
{
  "obj_type": "maximize",
  "obj_terms": [
    {
        "term_name": "TERM_SALES_REVENUE",
        "expression": "sum(VAR_PATH_FLOW[p] * PARAM_SELLING_PRICE[p[-1]] for p in FEASIBLE_PATHS)",
        "coefficient": 1,
        "desc": "销售收入：路径流量终点对应的需求单价"
    },
    {
        "term_name": "TERM_RESOURCE_COST",
        "expression": "sum(VAR_PATH_FLOW[p] * PARAM_RESOURCE_PRICE[p[0]] for p in FEASIBLE_PATHS)",
        "coefficient": -1,
        "desc": "资源采购成本：路径流量起点对应的资源单价"
    }
  ],
  "desc": "最大化总利润（销售收入 - 资源采购成本）"
}
```


#### 5. constraints（约束条件）

**核心原则**：**所有约束都基于路径流量变量（VAR_PATH_FLOW[p]）构建**

由于采用基于路径的建模方法，所有约束都通过对路径流量变量的聚合和过滤来表达：

**基本模式**：
- 资源容量：`sum(VAR_PATH_FLOW[p] for p in FEASIBLE_PATHS if p[0] == r) <= PARAM_CAPACITY[r]`
- 需求满足：`sum(VAR_PATH_FLOW[p] for p in FEASIBLE_PATHS if p[-1] == d) >= PARAM_DEMAND[d]`
- 节点能力：`sum(VAR_PATH_FLOW[p] for p in FEASIBLE_PATHS if node in p) <= PARAM_NODE_CAPACITY[node]`
- 边容量：`sum(VAR_PATH_FLOW[p] for p in FEASIBLE_PATHS if edge in p) <= PARAM_EDGE_CAPACITY[edge]`

**路径过滤技巧**：
- 起点过滤：`p[0] == resource_id`（路径第一个元素是起点节点）
- 终点过滤：`p[-1] == demand_id`（路径最后一个元素是终点节点）
- 中间节点过滤：`node_id in p`（节点在路径中）
- 边过滤：`edge_id in p`（边在路径中）

**示例**：
```json
{
  "constraint_name": "resource_capacity",
  "left_expression": "sum(VAR_PATH_FLOW[p] for p in FEASIBLE_PATHS if p[0] == r)",
  "direction": "<=",
  "right_expression": "PARAM_RESOURCE_CAPACITY[r]",
  "index_sets": ["RESOURCE_IDS"],
  "explanation": "所有从资源点r出发的路径流量之和不超过资源容量"
},
{
  "constraint_name": "demand_satisfaction",
  "left_expression": "sum(VAR_PATH_FLOW[p] for p in FEASIBLE_PATHS if p[-1] == d)",
  "direction": ">=",
  "right_expression": "PARAM_DEMAND[d]",
  "index_sets": ["DEMAND_IDS"],
  "explanation": "所有终点为需求点d的路径流量之和满足需求量"
}
```

**重要提示**：
- ❌ 不要使用边流量变量（如 VAR_FLOW[edge]）
- ❌ 不要添加流量守恒约束（已隐含在路径流量中）
- ✅ 所有约束都通过路径流量聚合表达

#### 6. solve_config（求解配置）

**求解器配置**：
- **solver_type 必须设置为 "scip"**

**配置示例**：
```json
{
  "solver_type": "scip",
  "solver_params": {
    "timeout": 300,
    "gap": 0.01,
    "threads": 4
  },
  "warm_start": false
}
```

**solver_params 参数说明**：
- `timeout`: 求解超时时间（秒），默认300秒
- `gap`: 相对最优性间隙，默认0.01 (1%)
- `threads`: 求解器线程数，默认4
- 其他可选参数根据SCIP求解器文档配置

#### 7. output_config（输出配置）

**输出字段定义**：
- 定义优化结果中需要输出的字段
- 包括决策变量值、目标函数值等
- 示例：
  ```json
  {
    "output_fields": [
      {
        "name": "path_flow",
        "expression": "VAR_PATH_FLOW",
        "desc": "路径分配流量"

      }
    ],
    "output_format": "json",
    "output_path": "./optimization_result"
  }
  ```

**输出格式**：
- 支持格式：csv, excel
- 默认使用 csv 格式
- output_path 指定输出文件路径（不含扩展名）

### 约束规则

1. **不包含实例数据**：DSL中只定义数据来源和结构，不包含具体数据

2. **路径数据处理**：
   - 路径格式：`[节点ID, 边ID, 节点ID, 边ID, ..., 节点ID]`
   - 路径集合：从paths_data表读取
   - 路径索引：路径列表本身作为索引键

3. **数据读取逻辑**：
   - 业务表数据：从source_table.source_field读取
   - 路径数据：从paths_data.paths读取
   - 参数计算：可能需要运行时从路径计算

4. **代码生成准备**：
   - DSL应包含足够信息生成完整代码
   - 包括数据读取、模型构建、求解调用
   - 最终代码应完整可运行
