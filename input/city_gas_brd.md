## §1 项目概述

### 1.1 项目背景

城燃公司（城市燃气分销企业）每月需要将上游天然气资源通过管网输送至各门站，满足终端客户的用气需求。当前面临的核心挑战：资源来源多样、管输路径复杂、客户需求差异大，需要在利润/成本/保供等多目标之间寻找最优匹配方案。

### 1.2 项目目标

构建一套月度天然气需供匹配与优化的运筹系统，实现：
- 自动化供需匹配方案生成
- 多目标（利润最大化/成本最优/保供优先，单选）优化决策支持
- 匹配方案的多版本管理与人工修正（基于最新版本复制创建新版本）
- 匹配方案的全链路可追溯

### 1.3 预期收益

- 提升月度经营计划编制效率和准确性
- 降低人工匹配的计算复杂度
- 实现利润/成本/保供的量化平衡
- 支持多方案对比，选出最优执行方案

## §2 业务范围

### 包含范围

| 编号 | 范围项 | 说明 |
|------|--------|------|
| S-001 | 经营计划管理 | 月度经营计划的制定、目标函数设定（无状态控制） |
| S-002 | 天然气需求管理 | 聚合后的天然气月度用气需求管理（匿名化，客户名称统一为城燃名称） |
| S-003 | 供应资源管理 | 天然气资源的采购与入库（LNG/PNG，状态：潜在/已购） |
| S-004 | 管输运力管理 | 管输路径与运力参数的管理（省际网/城际网/城燃网，状态：潜在/已购） |
| S-005 | 供需匹配优化 | 基于运筹算法的供需匹配方案生成 |
| S-006 | 匹配方案版本管理 | 基于最新版本复制创建新版本，版本号自增，支持多轮修正 |
| S-007 | 匹配结果管理 | 匹配结果的查看、分析与调整 |

### 不包含范围

| 编号 | 范围项 | 说明 |
|------|--------|------|
| X-001 | 客户档案管理 | 需求已聚合匿名化，不管理具体客户信息 |
| X-002 | 合同管理 | 采购/销售合同全生命周期管理不在本次范围 |
| X-003 | 实时调度 | 日内/实时天然气调度不在本次范围 |
| X-004 | 财务结算 | 匹配结果的财务结算不在本次范围 |
| X-005 | 方案导出 | 暂不考虑导出，页面交互友好查看即可 |

### 系统边界

- 匹配结果初始数据从外部业务系统对接导入
- 本系统负责方案的多版本修正、对比与确认

## §5 业务流程

### 5.1 主业务流程

```
[制定经营计划] → [录入天然气需求] → [录入供应资源] → [录入管输运力] → [导入初始匹配方案V1] → [人工修正] → [基于最新版本创建新版本] → [方案对比] → [确认执行方案]
```

### 5.2 方案版本管理流程

```
[外部系统导入V1] → [人工修正V1] → [基于V1创建V2] → [修正V2] → [基于V2创建V3] → [版本对比] → [确认选择最终版本]
```

### 5.3 异常流程

| 异常场景 | 触发条件 | 处理方式 |
|---------|---------|---------|
| 需求无法满足 | 供应资源不足以满足保供需求 | 提前预警，显示供需缺口 |
| 管输运力不足 | 管输能力不足以支撑匹配方案 | 展示运力利用率，辅助决策 |
| 资源无法送达 | 无可用管输路径 | 提示无可用路径 |

## §7 业务规则

### 对象不变式

| 编号 | 规则描述 | 适用对象 |
|------|---------|---------|
| INV-01 | 计划用气量 > 0 | 天然气需求 |
| INV-02 | 客户名称默认为城燃名称 | 天然气需求 |
| INV-03 | 资源量 > 0 | 供应资源 |
| INV-04 | 资源类型 ∈ {LNG, PNG} | 供应资源 |
| INV-05 | 资源状态 ∈ {潜在, 已购} | 供应资源 |
| INV-06 | 设计输气能力 > 0 | 管输运力 |
| INV-07 | 管网类型 ∈ {省际网, 城际网, 城燃网} | 管输运力 |
| INV-08 | 运力状态 ∈ {潜在, 已购} | 管输运力 |
| INV-09 | 交付量 > 0 | 供需匹配结果 |

### 行为前置条件

| 编号 | 适用行为 | 前置条件 |
|------|---------|---------|
| PRE-01 | 导入初始方案 | 经营计划已存在 |
| PRE-02 | 创建新版本方案 | 当前计划下至少存在一个版本 |
| PRE-03 | 确认方案 | 同一经营计划下无其他已确认方案 |

### 行为后置条件

| 编号 | 适用行为 | 后置条件 |
|------|---------|---------|
| POST-01 | 导入初始方案 | 版本号 = 1，方案状态 = 初始导入 |
| POST-02 | 创建新版本方案 | 版本号 = 最新版本号 + 1，匹配结果从最新版本复制 |
| POST-03 | 修正匹配结果 | 自动重算进销差价、利润、管输费，并更新方案汇总 |
| POST-04 | 确认方案 | 方案状态 = 已确认 |
| POST-05 | 删除匹配结果 | 自动更新方案总交付量和总利润 |

| REL-03 | 匹配结果.管输编号 必须存在于 管输运力 |
| REL-04 | 匹配结果.需求编号 必须存在于 天然气需求 |
| REL-05 | 管输运力的下载站→门站路径必须在管网拓扑中可达 |

### 业务规则

| 编号 | 规则描述 | 说明 |
|------|---------|------|
| BIZ-01 | 保供优先：必须供气的需求不可被忽略 | 供需匹配核心约束 |
| BIZ-02 | 照付不议：资源实际提取量 ≥ 最小提气量 | 否则按最小提气量计费 |
| BIZ-03 | 管输能力上限：实际输气量 ≤ 设计输气能力 | 管输物理约束 |
| BIZ-04 | 管输保底下限：实际输气量 ≥ 保底量 | 管输合同约束 |
| BIZ-05 | 多气源多路径：同一需求可由多个资源通过不同管输路径满足 | 灵活匹配 |
| BIZ-06 | 目标函数驱动：匹配方案由经营计划的经营目标（单选）驱动优化 | 优化方向 |

### 计算规则

| 编号 | 规则名称 | 计算公式 | 说明 |
|------|---------|---------|------|
| CALC-01 | 进销差价 | 用户报价 - 资源采购价 | 匹配结果 |
| CALC-02 | 利润 | 进销差价 - 运力采购价 | 匹配结果 |
| CALC-03 | 管输费 | 交付量 × 运力采购价 | 匹配结果 |
| CALC-04 | 方案总交付量 | SUM(匹配结果.交付量) | 方案汇总 |
| CALC-05 | 方案总利润 | SUM(匹配结果.利润) | 方案汇总 |
