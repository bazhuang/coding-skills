# repo-wiki Windows 适配修复计划（P0 真实 Bug）

只修当前 Windows/Git Bash 环境下实测会坏的问题，写文件策略改用 Write 工具。共改 4 个文件。

## 改动 1：脚本 `--output` 父目录自动创建（修实测崩溃）
scan_repo.py 实测 `--output docs/tmp/xxx.json` 时父目录不存在直接 FileNotFoundError。
在 3 个脚本的 `open(args.output, "w")` 之前各加一行 `os.makedirs(os.path.dirname(os.path.abspath(args.output)), exist_ok=True)`：
- scripts/scan_repo.py:131-132
- scripts/scan_api_entries.py:162-163
- scripts/parse_structure.py:239-240

## 改动 2：扫描输出路径分隔符统一正斜杠（修增量 hash 失配 + Markdown 链接断裂）
Windows 下 os.path.relpath/join 输出反斜杠，导致 file_hashes key 跨平台对不上、{FILE_PATHS_LINKED} 生成的 Markdown 链接无效。

- scripts/scan_repo.py:96-98 — rel_dir/rel_file 生成后 .replace(os.sep, "/")，让 file_tree/file_hashes key 都是正斜杠
- scripts/scan_api_entries.py:82 — rel_path 同样 replace 成正斜杠
- scripts/export_wiki.py:106 — build_page_dir 返回 os.path.join(*chain) 后 .replace(os.sep, "/")
- scripts/export_wiki.py:305,614 — page_id_to_file 拼接处：实际磁盘写入用 os.path.join（OS 原生），写进 meta.yaml/Markdown 链接的值用正斜杠版本。两路分开。

## 改动 3：SKILL.md 写文件规则改用 Write 工具（用户确认方向）
- 重写第 12-30 行「写文件规则（全局约束）」整段：删除「禁止使用 Write 工具」约束、heredoc 示例；改为用 Write 工具写临时文件，已存在时先 Read 再 Write 或 rm -f 后 Write。
- 步骤 3、4 里 3 处「按 shell heredoc 写入」措辞改为「用 Write 工具写入」（134、169、175 行附近）。

## 不改的内容（本次明确不动）
python3→python、rm -rf/mkdir -p 命令、rg 兜底、shebang、EXCLUDED_DIRS 补 Windows 目录、verify_wiki.py 链接解析。属增强项，不在 P0 范围。
