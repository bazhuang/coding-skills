# Repo Wiki Skill 实现计划（结构已定稿）

## 结构决策（已定）

- **磁盘布局 = 扁平**：所有文章平铺 `docs/wiki/<slug>.md`，文件名=slug；父子层级只编码在 `wiki-tree.json` 的 `parent` 字段。
- **交叉引用 = 纯 slug**：`[JWT 认证](jwt-auth)`（无路径），同目录下 GitHub 自动解析 `.md`。忠实于 Qoder 的 slug 解耦设计，重命名只动一个文件+JSON。
- **章节结构 = 直接采用 Qoder 5 类型 H2 序列**（已验证成熟，见下）。
- **catalog = Qoder `wiki-tree.json` schema**（slug/title/type/objective/modules/parent/need_further_planning）。
- **跨切面 6 类别 = 折叠进 developer_guide**（不单列 repo-knowledge/ 子树）。

## wiki-tree.json schema（移植 Qoder directory_schema）

```json
{
  "articles": [
    {
      "slug": "overview",            // ASCII [a-z0-9_-], 1-40, 全局唯一
      "title": "项目概览",            // 本地化标题 = 文章 # 标题
      "type": "overview",            // overview|getting_started|domain|deep_dive|developer_guide
      "objective": "定位... 不在范围内：各领域细节",  // 1-2句，含out-of-scope
      "modules": ["/"],              // 模块路径（从模块树原样复制）
      "parent": "",                  // 父 slug；空=顶层
      "need_further_planning": false  // bool，触发子层递归
    }
  ]
}
```
硬上限：总文章 ≤30、顶层 ≤8、子/父 ≤6、深度 ≤3。覆盖规则：模块树每个模块须出现在至少一篇文章的 modules（跨所有层级）。

## 章节结构（每类型固定 H2 序列，移植 Qoder，结构是建议——无内容则跳过）

| type | H2 序列 |
|---|---|
| **overview** | 引言(1-2段) → 高层架构(`graph TB`+正文) → 核心能力(列表/表格) → 模块/子领域映射(每子文章一段+`[子标题](slug)`) |
| **getting_started** | 前置条件 → 安装步骤(编号+命令块) → 首次运行(命令+预期输出) → 常用工作流(3-5) → 故障排除?(可选) |
| **domain** | 领域引言 → 子领域映射(`graph TB`) → 跨组件流程(`sequence`) → 设计决策(ADR式) → 子领域文章(列表+链接) |
| **deep_dive** | 模块引言(1-2段) → 架构(`class`图+正文+`Diagram sources`) → 核心组件(每类一个`###`+`Section sources`) → 数据流(`sequence`) → 配置?(表格) → 源文件映射 |
| **developer_guide** | 项目布局(目录树) → 构建与测试 → 编码规范 → 常见任务 → 故障排除?(可选) |

**硬规则**：首行 `# <标题>`(单H1)；`##`/`###`/`####` 无 `#####`+；无目录 section（渲染器自动生成）；无总结/结论/Next Steps；无 frontmatter；deep_dive 重源码引用、overview/domain 重综合+链接。

**引用格式**：显示 `[file.go:15-30]`（纯数字无L前缀），URL `file://path#L15-L30`（有L前缀）；`**Section sources**`/`**Diagram sources**` 块。

**Mermaid**：class/sequence/flowchart/graph/ER；无自定义样式、双引号标签、`<br/>`换行、节点ID仅字母数字下划线。

## 工作流程（三阶段）

**阶段1 模块合成**（module-synthesis.md）：全量枚举源码树（仅排默认glob，禁止采样）→ 模块树（路径+描述+`[N子模块]`）→ 逐模块提取 description/architecture_design(主信号)/tech_stack/coding_conventions/unique_setup/scope/source_files/dependencies/related。大项目按顶层目录分区派发 `Explore` 子代理（只读inspect+summarize，主agent写）。落 `.module-tree.md`。

**阶段2 目录规划**（catalog-planning.md+directory-schema.md）：先草拟 `_plan.md`（意向页+源码证据+待确认）→ 物化 `wiki-tree.json`（递归单层，max_depth≤3）→ 清理pass（合并薄stub/删单文件目录/删`_plan.md`）。5类型指南+`need_further_planning`判定(≥4模块+≥3子域+超max_words)。吸收可选`wiki-plan.yaml`。硬上限+覆盖率验证。

**阶段3 自底向上文章生成**（article-templates.md+citation-diagram-rules.md）：叶子(deep_dive)先写→父(domain)综合子summary+key_topics而非重复→顶层overview最后综合。按类型套H2模板。Mermaid+引用严格格式。16项自检。写边界：仅写`docs/wiki/`。

## 准出门禁（coverage-gates.md）
1. `wiki-tree.json` schema校验通过（slug全局唯一/类型合法/无空modules/parent指向有效slug）。
2. **覆盖率100%**：模块树每个模块出现在≥一篇文章modules；未达不得准出。
3. 每篇首行`# <标题>`，无frontmatter/目录/总结section。
4. Mermaid可解析；引用格式合规；每篇assigned modules在正文≥出现一次。
5. 父文章`[子标题](slug)`引用子文章而非重复。
6. 清理pass已执行：无薄stub（OpenWiki借鉴）。
7. `validate_repo_wiki.py`通过（无FAIL）。

## 范围

## 关键原则
- 代码=唯一事实源，wiki=派生视图，不臆造。
- 阶段提示词化+agent自主原生工具执行（OpenWiki模型）×Qoder结构化输出质量。
- 全量枚举保覆盖；大项目只读并行Explore子代理；覆盖率<100%不准出。
- slug纯链接解耦物理与逻辑（Qoder设计）；wiki-tree.json=层级单一真相源。
- 主文件短小，细则下沉references按需读。
