# or_ontology 到 or_dsl 规则

本文件给出从 `or_ontology` 或标准化输入生成运筹 DSL `or_dsl` 时需要遵循的规则。

## 1. or_dsl 定位

- `or_dsl` 是代码生成蓝图，不是数据容器
- `or_dsl` 只定义数据来源、模型结构、求解配置和输出配置
- `or_dsl` 不包含实例数据

## 2. data_def.tables

保留原则：

- 保留参与优化计算的核心业务表
- 保留在目标或约束中被引用的表
- 保留包含约束度量、目标度量、边界度量或成本度量的表

可过滤对象：

- 纯关系表，且其信息已经由路径数据覆盖
- 无约束字段的透传节点表
- 纯元数据表

字段精简原则：

- 过滤纯元数据字段
- 保留业务字段、主键、外键、约束相关字段

## 3. data_def.index_sets

- 从业务表提取所有离散集合
- 集合来源要明确到表和字段
- 路径型场景必须定义 `FEASIBLE_PATHS`
- 时间离散场景必须定义对象-时段组合集合，而不只是单独的时段集合
- 对每个时段切片业务对象，使用对象标识维度与时间维度形成组合集合
- 组合集合的 `source` 指向来源表，`source_fields` 同时列出对象标识字段与时间维度字段
- 路径型时间离散场景必须定义路径-时间可行域
- 路径-时间可行域是派生集合，来源表达使用 `derived.*`，其语义由路径集合和各对象-时段组合集合共同约束
- 路径-时间可行域不能直接复用任一单一对象-时段组合集合
- 不要因为多个业务表都含有时间维度字段，就默认它们共享同一时间集合
- 只有输入明确提供统一日历、统一离散化规则、跨对象时间对齐关系或等价声明时，才额外定义统一 `TIME_PERIODS`
- 统一时间集合可使用共享时间域来源表达，并用 `source_fields` 列出全部参与共享时间域的来源字段
- 若缺少共享时间域依据，应保留对象-时段组合集合，并显式指出缺少跨对象时段对齐依据；不要取交集、并集或任选一个表作为默认时间集合
- `FEASIBLE_PATHS` 的描述里要说明路径格式
- 对时间离散的路径型场景，只有存在统一时间域时，建模主轴才应理解为 `FEASIBLE_PATHS x TIME_PERIODS`

## 4. data_def.parameters

- 数值业务字段优先映射为参数
- 参数名使用 `PARAM_` 前缀
- 参数要明确来源、索引集合、数据类型和业务含义
- 价格类参数必须说明价格类型
- 若源表是时段切片表，不要把所有字段都默认索引到对象-时段组合集合
- 默认只有数量类、容量类、上下界类、保底类、计划类、最小满足类、强制满足标记类等受时段切片影响的度量，才索引到对应对象-时段组合集合
- 价格类、名称类、状态类、类型类、组织类、参与方类、路径描述类等属性默认不考虑与时间维度的对应关系
- 价格类参数默认按对象集合索引
- 只有输入明确声明价格随时段变化时，价格类参数才允许索引到对象-时段组合集合
- 不要在参数 `index_sets` 中写裸字段名；应引用已定义的索引集合或组合集合

## 5. decision_vars

- 变量名使用 `VAR_` 前缀
- 变量只围绕真实决策建立
- 路径型场景必须优先定义路径流量变量
- 静态路径场景下，路径变量索引为 `FEASIBLE_PATHS`
- 时间离散路径场景下，核心路径流量变量应索引路径-时间可行域
- 不要让核心路径流量变量直接索引任一单一对象-时段组合集合
- 若输入明确给出统一时间域，也要通过路径-时间可行域承载路径与时间的可行组合
- 若只有多个对象级时段字段而没有统一时间域依据，不要直接生成共享 `t` 的路径流量变量，应先暴露时间对齐缺口或等待上游补充时间映射
- 不要在主变量之外无依据扩张出边流量、节点流量等平行变量体系

## 6. objective

- 目标拆成 `obj_terms`
- 每个子项包含名称、表达式、系数和业务描述
- 总体目标描述要能概括所有子项
- 时间离散路径场景下，目标子项优先表达为对 `p` 与 `t` 的双重求和或按 `t` 固定后的路径聚合
- 若表达式使用 `t`，应在表达式文本中显式出现 `for t in TIME_PERIODS` 或等价的时段绑定，不要仅靠 `index_sets` 隐式传达

## 7. constraints

- 所有约束必须有唯一 `constraint_id`
- 约束表达式必须能追溯到参数、变量、集合
- 路径型场景下，约束应通过路径流量聚合表达
- 时间离散路径场景下，先分析每条约束的时间作用域，再决定 `VAR_PATH_FLOW` 在该约束中是按单时段聚合还是按跨时段聚合
- 当 `index_sets` 中包含 `TIME_PERIODS` 时，`left_expression` 与 `right_expression` 也应显式体现时段变量 `t`
- 约束左右两侧必须共享一致的时间粒度；禁止把单时段左侧表达式与静态右侧参数直接配对
- 若右侧参数只有静态对象索引，则该约束不能伪装成按时段约束；应改写为跨时段聚合约束，或回到上游补充时段化参数依据
- 也就是说，路径流量的时间聚合维度是由约束时间口径决定的，而不是先验固定的

典型路径过滤：

- 起点对象：按路径首个对象过滤
- 终点对象：按路径最后一个对象过滤
- 中间对象：按路径成员关系过滤
- 连接对象：按路径成员关系过滤

典型时空路径过滤：

- 固定起点对象与时段：按路径起点过滤并在对应时段聚合路径流量
- 固定终点对象与时段：按路径终点过滤并在对应时段聚合路径流量
- 固定中间连接对象与时段：按路径成员关系过滤并在对应时段聚合路径流量

时间粒度一致性示例：

- 正确：单时段左侧聚合应与同一对象-时段口径的右侧参数配对
- 正确：若右侧参数是静态对象口径，左侧应明确做跨时段聚合
- 错误：左侧表达式含时间变量但右侧仍使用静态对象口径，且未声明跨时段聚合

约束驱动的时间聚合理解：

- 若右项参数是对象-时段组合口径，左项通常应保持单时段聚合
- 若右项参数是静态对象口径且语义是总量/累计量，左项通常应对时间维度做跨时段聚合
- 若输入无法判断右项是时段量还是总量，不要臆造；应保守暴露缺口

路径型场景特别注意：

- 不要使用边流量变量替代路径流量变量
- 不要额外添加流量守恒约束
- 若输入对象是时段切片对象，不要把时间维度从受时段影响的参数索引和约束作用域中删掉

## 8. solve_config

- `solver_type` 默认使用 `scip`
- 常用参数包括超时、精度或 gap、线程数

## 9. output_config

- 输出字段围绕变量结果、目标值和关键业务摘要
- 输出格式通常使用 `json`、`csv` 或 `excel`
- 时间离散路径场景下，输出字段应明确体现路径-时段联合粒度；不要只输出不带时间维说明的 `VAR_PATH_FLOW`

## 10. 输出格式

- 最终必须输出完整 `or_dsl` JSON
- JSON 必须可直接解析
- JSON 必须覆盖 schema 要求的全部顶层模块
