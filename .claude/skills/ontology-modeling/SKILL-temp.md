# 本体论建模指导

使用**对象(Object)、行为(Behavior)、规则(Rules)**三要素方法论进行业务领域建模。

## 核心方法论

### 本体三要素

| 要素 | 定义 | 问题 |
|------|------|------|
| **对象(Object)** | 系统中真实存在的业务实体 | What exists? |
| **行为(Behavior)** | 对象能够执行或承受的动作 | What can be done? |
| **规则(Rules)** | 约束对象状态转换和行为执行的不变式 | What must hold? |

### 核心原则

1. **对象是第一性的**：先定义存在什么对象，再定义行为
2. **行为改变对象状态**：每个行为必然导致至少一个对象的状态变化
3. **规则是不变式**：无论何时何地，规则永远成立（Invariant）
4. **对象链即流程**：对象之间的引用关系自然形成业务流转路径

#### 步骤1：需求理解与领域分析

- 加载知识源进行分析

#### 步骤2：对象层(Object Layer)建模

##### 对象(Object)

- **定义**：业务领域中的所有实体对象，具有独立生命周期
- **特征**：可被创建、查询、更新、删除(CRUD)
- **示例**：合同、需求、订单、用户、站点
- **属性特殊说明**：业务对象类型 如果命中了知识库references/opt.md的文档，就增加biz_object_type 即需供运筹元模型中Node对应业务对象类型的code

##### 关系(Value Object)

- **定义**：表达对象之前的依赖关系
- **特征**：有主对象和附属对象
- **示例**：节点到节点的运输关系
- **属性特殊说明**：业务对象类型 如果命中了知识库references/opt.md的文档，就增加biz_object_type 即需供运筹元模型中Edge对应业务对象类型的code

#### 步骤3：行为(Behavior)

##### 创建行为(Update) [U]

- **语义**：使对象从无到有
- **前置条件**：无对象实例存在
- **后置条件**：对象实例被创建

**提问**：

- 如何使这个对象从无到有？

##### 更新行为(Update) [U]

- **语义**：改变对象的属性值或状态
- **前置条件**：对象必须存在
- **后置条件**：对象属性已变更

**提问**：

- 如何改变对象的属性值或状态？

##### 查询行为(Query) [Q]

- **语义**：读取对象但不改变状态
- **前置条件**：对象可能存在或不存在
- **后置条件**：返回对象数据

**提问**：

- 需要查询这个对象的哪些信息？

##### 删除行为(Delete) [D]

- **语义**：使对象失效(物理删除或逻辑删除)
- **前置条件**：对象必须存在
- **后置条件**：读取对象不可再访问

**提问**：

- 如何使这个对象失效？

#### 步骤4：规则层(Rules Layer)建模

识别约束规则：

##### 关系约束(Relationship Constraint)

- **定义**：对象之间引用关系必须满足的约束
- **符号**：平行四边形，紫色
- **验证时机**：建立关联关系时
- **示例**：开票.合同ID 必须存在于 合同表

**提问**：

- 对象之间的引用关系必须满足哪些约束？

##### 业务规则(Business Rule)

- **定义**：领域特定的复杂约束逻辑

**提问**：

- 这个领域有哪些特定的复杂约束逻辑？

#### 步骤5：提取总结业务场景的工作流程 SOP

- 提取总结业务场景的工作流程 SOP
- 或者提醒用户补充或者优化工作流程

#### 步骤6：生成业务场景方案（类似BRD）

关键要点：**根据以上提取出的所有信息, 使用SKILL brd-scenario-generator 总结出的业务场景方案，一个BRD文档方案， 作为后续回复用户的内容之一**
注意：必须使用 SKILL brd-scenario-generator 生成这个 生成业务场景方案（类似BRD）

#### 步骤7：生成建模schema并保存

**重要原则：schema 应在整个多轮建模过程中持续生成和更新，而非仅在最后一步生成。**

这意味着：

- 步骤6的 {{业务场景方案}} 更新到 schema 的 biz
- 识别提炼业务逻辑，将用户所有对话中对业务目标、业务场景和工作流程的描述进行提炼，拼接起来 更新到 schema的 biz_logic
- 识别出第一个对象Object时，就应生成包含该对象的初始 schema
- 用户补充属性后，更新 schema 中该对象的 properties
- 识别出关系后，更新 schema 的 edges
- 识别出行为后，更新 schema 的 behaviors
- 识别出规则后，更新 schema 的 rules
- 识别出业务流程后，更新 schema 的 sop

##### 文件保存操作

**按以下json格式生成JSON，并使用`mcp__graph__data_write` tool 将JSON内容写入到项目根目录下的`ontology-{fingerprint}.json`文件中，其中`{fingerprint}`'的值是根目录下`.app_config.json`中key=fingerprint的value值**

**注意：必须使用 `mcp__graph__data_write` tool**

```json
{
    "biz_logic": "",
    "biz": "",
    "objects": [],
    "edges": [],
    "rules": [],
    "behaviors": [],
    "sop":[]
}
```

json中每个字段的解释如下

```ts
interface Ontology {
  biz_logic: string; // 业务逻辑，将用户的对话中对业务场景和工作流程的提炼，拼接起来
  biz: string; // {{业务场景方案}}
  domain: string; // 业务场景归属的领域
  objects: OyObject[];  // 实体对象列表
  edges: OyEdge[]; // 本体中的关系列表
  rules: Rule[]; //分析提取出来的业务规则约束
  behaviors: Behavior[] // 分析提取出哪些行为
  sop: SOP[]; // 分析业务场景，总结出SOP流程
}
```

输出标准格式的建模schema：

Directly output the raw JSON format of `Ontology` without any Markdown code block wrappers (e.g., do not include "```json" or "```"). The output must strictly adhere to the `Plan` interface defined below:

```ts
interface OyObject {
  code: string; // 对象code，仅包括英文、下划线，长度控制在32个字符
  name: string; // 对象名称
  comment: string;// 有关于对象的扩展信息
  type: string; // 对象类型，如：核心对象，实体对象
  properties: OyProperty[]; // 对象的属性列表
}

interface OyProperty {
    code: string; // 属性code，仅包括英文、下划线，长度控制在32个字符
    name: string; // 属性名称
    comment: string; // 属性描述
    type: string; // 属性值的类型，仅允许展示String、Integer、Double
}

interface OyEdge {
    code: string; // 关系code，仅包括英文、下划线，长度控制在32个字符
    name: string; // 关系名称
    comment: string; // 关系的描述
    source_code: string; // 表达关系的来源对象code
    target_code: string; // 表达关系的去向对象code
    constraint: string; // 对象之前的关系约束
}

interface Rule {
    code: string; // 约束规则的唯一编码，根据内容生成，确保唯一性。长度控制在64个字符
    description:string; // 约束规则的内容
}

interface Behavior {
   type: string; // C U R D 4个字母之一，对应创建/更新/查询/删除
   description: string // 行为对应描述
}

interface SOP {
    step: string; // 业务流程步骤序号
    description:string; // 业务流程的内容
}
```
