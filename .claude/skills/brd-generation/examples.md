### 4. 业务流程

#### 4.1 主业务流程（订单生命周期）

```
用户下单 → 扣减库存 → 等待付款
  → 付款成功 → 订单流转到仓储
    → 拣货 → 打包 → 发货（生成物流单号）
      → 用户收货 → 订单完成
  → 付款超时 → 释放库存 → 订单取消
```

#### 4.2 退款流程

```
用户申请退款 → 客服审核
  → 审核通过 → 退款处理（财务） → 退款到账 → 恢复库存
  → 审核拒绝 → 通知用户（附拒绝原因）
```

### 5. 功能需求

#### 5.1 订单管理模块

| 编号 | 功能名称 | 优先级 | 描述 |
|------|---------|--------|------|
| F-001 | 创建订单 | 必须 | 用户选择商品提交订单，系统自动生成订单号 |
| F-002 | 订单详情查看 | 必须 | 查看订单完整信息（商品、金额、物流、状态） |
| F-003 | 订单列表查询 | 必须 | 支持按状态、时间、客户等条件筛选订单 |
| F-004 | 取消订单 | 必须 | 付款前用户可自行取消，付款后需客服介入 |
| F-005 | 订单状态追踪 | 必须 | 实时显示订单当前状态及流转历史 |

#### 5.2 库存管理模块

| 编号 | 功能名称 | 优先级 | 描述 |
|------|---------|--------|------|
| F-006 | 库存锁定 | 必须 | 下单时锁定对应商品库存 |
| F-007 | 库存扣减 | 必须 | 发货后实际扣减库存 |
| F-008 | 库存释放 | 必须 | 订单取消或退款后释放锁定库存 |
| F-009 | 库存预警 | 应该 | 库存低于阈值时触发预警通知 |

#### 5.3 仓储发货模块

| 编号 | 功能名称 | 优先级 | 描述 |
|------|---------|--------|------|
| F-010 | 待发货订单池 | 必须 | 展示所有待发货订单，支持排序和分配 |
| F-011 | 拣货确认 | 必须 | 仓管确认拣货完成 |
| F-012 | 打包确认 | 必须 | 仓管确认打包完成 |
| F-013 | 发货登记 | 必须 | 录入物流公司和物流单号，完成发货 |
| F-014 | 物流信息同步 | 应该 | 自动同步物流轨迹信息 |

#### 5.4 退款售后模块

| 编号 | 功能名称 | 优先级 | 描述 |
|------|---------|--------|------|
| F-015 | 退款申请 | 必须 | 用户提交退款申请，选择退款原因 |
| F-016 | 退款审核 | 必须 | 客服审核退款申请，通过或拒绝 |
| F-017 | 退款执行 | 必须 | 财务确认退款到账 |
| F-018 | 退款进度查看 | 必须 | 用户查看退款处理进度 |

#### 5.5 运营分析模块

| 编号 | 功能名称 | 优先级 | 描述 |
|------|---------|--------|------|
| F-019 | 订单统计看板 | 应该 | 展示订单量、金额、转化率等关键指标 |
| F-020 | 异常订单监控 | 应该 | 监控超时未付款、超时未发货等异常订单 |

### 6. 业务规则

#### 6.1 订单规则

| 编号 | 规则描述 | 规则类型 |
|------|---------|---------|
| R-001 | 订单金额 = 所有订单明细小计之和 | 计算规则 |
| R-002 | 付款超时时间默认30分钟，超时自动取消 | 流程规则 |
| R-003 | 已付款订单取消需客服审核 | 流程规则 |
| R-004 | 订单一旦发货不可取消，只能走退款流程 | 流程规则 |

#### 6.2 库存规则

| 编号 | 规则描述 | 规则类型 |
|------|---------|---------|
| R-005 | 下单时库存不足则不允许创建订单 | 数据规则 |
| R-006 | 锁定库存 ≤ 可用库存 | 数据规则 |
| R-007 | 退款完成后恢复对应商品的锁定库存 | 流程规则 |

#### 6.3 退款规则

| 编号 | 规则描述 | 规则类型 |
|------|---------|---------|
| R-008 | 退款金额 ≤ 订单实付金额 | 数据规则 |
| R-009 | 已发货订单仅支持退款退货，不支持仅退款（建议确认） | 流程规则 |
| R-010 | 退款审核应在48小时内完成 | 流程规则 |

#### 6.4 权限规则

| 角色 | 可查看 | 可操作 |
|------|--------|--------|
| 客服 | 所有订单信息 | 退款审核、订单取消（已付款） |
| 仓管 | 订单商品信息和收货地址 | 拣货、打包、发货确认 |
| 财务 | 订单金额、退款金额 | 退款执行确认 |
| 运营 | 所有订单数据（脱敏） | 订单监控、数据导出 |

## 使用建议

1. **灵活运用**：不同项目的复杂度不同，步骤可以灵活调整
2. **持续迭代**：BRD 生成后可以反复调整，直到满足需求
3. **注重确认**：每一步都和用户确认，避免理解偏差
4. **推理辅助**：基于已有信息主动推理和补充，但要让用户决策
5. **按需裁剪**：如果项目简单，某些章节可以简化或合并
