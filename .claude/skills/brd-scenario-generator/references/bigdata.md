# 天然气需供匹配场景知识库

## 场景描述

天然气需供运筹匹配业务：基于需供经营计划，资源池、需求池、传输运力池之间的最优匹配的方案是通过运筹优化模型求解，最终生成需供运筹匹配结果。天然气通过资源池的资源下载站点经过传输网络的运力，送到需求池的客户门站，传输运力和站点都有运输限制，最终全局匹配所有约束，得到需供匹配方案，业务对象层面需要区分年度、月度、日度等不同维度。此场景给天然气城燃业务人员提供方案。

---

## 详细说明

### 1. 天然气经营计划 → 运筹优化模型

**关系**：指导匹配目标设定
**业务含义**：

- 匹配原则：保证价值最大化的基础上满足客户需求
- 价值计算公式：销售收入 − 资源成本 − 运力成本 − 资源照付不议成本 − 需求缺口成本 − 运力低于最小量成本

---

### 2. 需求 → 运筹优化模型

**关系**：需求侧匹配的边界条件
**业务规则**：

- 核心原则：为每位客户实际匹配的总气量 ≤ 原计划的需求总量
- 客户分类策略：
  - **必须供气 + 不允许打折**：完全按照计划量满足
  - **必须供气 + 允许灵活供应**：在最低需求量 ~ 计划量之间安排
  - **非必须供气 + 不允许打折**：要么完全满足，要么暂不供应
  - **非必须供气 + 允许灵活供应**：在最低需求 ~ 计划量之间灵活匹配，也可能暂不供应
- 制定一个或多个运输终点站点

---

### 3. 资源 → 运筹优化模型

**关系**：资源侧匹配的边界条件
**业务规则**：

- 资源使用总量约束：每份资源合同的匹配气量总和 ≤ 当月资源池可用总量
- **照付不议成本计算**：
  - 已签约资源未达最低提气量时：（最低提气量 − 匹配总量）× 资源单价 × 照付不议系数（如0.3）
  - 潜在未签约资源：照付不议成本为零
- 制定一个或多个运输终点起点

---

### 4. 传输运力池 → 运筹优化模型

**关系**：传输网络侧匹配的边界条件
**业务规则**：

- 管道运力上限：当月承载的总匹配气量 ≤ 设计输气能力
- 管道运力保底量：运输保底量 ≤ 当月匹配气量
- 包含运输起点站点和运输终点站点
- **运输成本计算**：
  - 运输费用：匹配总量 × 管输单价
- **保底量运输成本计算**：
  - 匹配运力总量未达保底量时：保底量 × 管输单价

---

### 7. 运输线路-起点 → 资源

**关系**：运输服务起点
**说明**：资源下载站点，是资源的注入点

---

### 8. 运输线路-终点节点 → 需求

**关系**：运输服务终点
**说明**：需求门站站点是终点节点，连接需求侧，是资源的提取点

---

### 9. 运筹优化模型 → 需供运筹匹配结果

**关系**：求解并存入结果
**处理流程**：

1. **求解模型**：求解方式：例如算法计算求解结果存入匹配结果
2. **结果整合存储**：生成结构化的匹配结果记录集，作为后续调度执行与财务结算的唯一权威依据

---

## 核心规则汇总

### 需求侧规则

| 规则 | 说明 |
|------|------|
| 总量约束 | 实际匹配气量 ≤ 原计划需求总量 |
| 必须供气+不打折 | 完全按计划量满足 |
| 必须供气+可灵活 | 在最低需求 ~ 计划量之间安排 |
| 非必须+不打折 | 要么完全满足，要么暂不供应 |
| 非必须+可灵活 | 在最低需求 ~ 计划量之间灵活匹配 |
| 动态触发 | 客户需求计划更新 → 自动重新匹配 |

### 资源侧规则

| 规则 | 说明 |
|------|------|
| 合同约束 | 匹配气量 ≤ 资源池可用总量 |
| 照付不议成本 | （最低提气量 − 匹配总量）× 资源单价 × 系数 |
| 动态触发 | 资源池属性变动 → 自动重新匹配 |

### 传输运力池规则

| 规则 | 说明 |
|------|------|
| 运力上限 | 匹配气量 ≤ 设计输气能力 |
| 运力照付不议 | （保底量 − 匹配总量）× 管输单价 |
| 动态触发 | 管输池属性变动 → 自动重新匹配 |

### 价值计算规则

```
利润 = 销售收入
     − 资源成本
     − 运力成本
     − 资源照付不议成本
     − 需求缺口成本
     − 运力低于最小量成本
```

## 建模提示

### 每个对象的标准属性（10个）

所有对象都包含以下通用属性：

1. cvcu_id（客创ID）
2. create_by（创建人）
3. create_time（创建时间）
4. update_by（修改人）
5. update_time（修改时间）
6. 如果是月度对象 需要增加字段 开始日期和结束日期 start_data end_data
7. 如果是年度对象 需要增加字段 年 year
8. 如果是日度对象 需要增加字段 日期 data

### 需要补充的业务属性

在实际建模访谈中，如果没有，需要引导用户补充以下业务属性：

**需求对象**：

- 需求量、最低需求量、优先级、客户类型（民用户/工商户/大客户）

**供给对象**：

- 资源量、合同量、最低提气量、资源单价、照付不议系数

**运输线路对象**：

- 设计输气能力、运力状态（已购/未购）、保底量、管输单价

**需供运筹优化模型对象**：

- 没有对象，提醒用户添加
- 提醒用户优化模型对象是通过什么方式求解，是一个算法工具，还是其他

**需供运筹匹配结果对象**：

- 没有对象，提醒用户添加
- 匹配结果中有分配的资源、分配气量、满足的需求，分配路径
