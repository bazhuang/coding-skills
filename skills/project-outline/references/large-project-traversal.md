# 大型项目分区并行遍历

本文件定义大型项目（源码文件 > 200 或入口点 > 80、多模块/monorepo）的全量枚举策略：分区、并行子代理枚举、合并去重。仅当步骤 1 判定项目规模为"大"时读取。

## 为什么必须分区

单代理无法在上下文内装下大库的全部源码——必然退化为"读到哪写到哪"的采样，这是项目大纲漏功能的根因。分区并行枚举让每个子代理只负责一个可装下的分区，穷举该分区的入口/模块/实体，再合并，才能保证覆盖。

## 分区策略

1. 按业务子域/顶层模块分区：以步骤 1 识别的顶层模块（Maven 多模块 / monorepo 子包 / 顶层目录）为天然边界，保证业务内聚。**按业务子域切，不要按技术层（controller/service/model）切**——技术层切面会把一个功能拆到多个分区，跨区拼凑不出功能全貌。
2. 每区体量控制在子代理可读范围：源码文件 ≤ ~50 或入口点 ≤ ~30；过大则按子目录再拆，过小则合并相邻目录。
3. 主分区按模块切；跨切面分区（如"所有 Controller 文件"）仅作补充，用于核对模块分区是否漏入口。
4. 产出分区清单：`分区名 / 路径 / 负责维度(入口·模块·实体) / 预期入口数`。
5. 设分区预算：每区源码文件 ≤ ~50、枚举深度 ≤ ~3 层、并发子代理数按分区数但不超过运行环境上限；超出预算的区继续拆。预算避免大库遍历爆炸。

## 并行子代理枚举模板

每个子代理负责一个分区的穷举枚举，只枚举不归类。模板：

```
你负责枚举分区 [分区名]（路径：[路径]）的全部业务信号，只枚举不归类。
用 grep/搜索确定性信号穷举，不靠逐文件阅读"注意到"：
- 入口点：[栈对应的枚举信号，见 tech-detection-guide.md]
- 数据模型：[实体信号：@Entity/@TableName/__tablename__/CREATE TABLE]
- 顶层模块/子包

输出分片清单，每项含：类型(入口/实体/模块)、名称、文件路径、入口签名。不判断业务含义、不写 prose，只产结构化清单。预期入口数 [N]，若枚举数明显少于预期，说明可能漏了，再扫一遍该分区。
```

子代理数量与并发由主代理按分区数决定；分区相互独立，无写冲突。子代理返回的分片清单由主代理合并。

## 合并与去重

1. 汇总各分片清单为全局枚举基线（步骤 2 的产出）。
2. 去重：同名入口/实体跨区出现时，按 `文件路径:签名` 去重，保留首次出现并记录跨区引用。
3. **边界核对**（分区遍历的典型风险）：检查分区交界处的入口/实体是否被两边都声明或都漏掉。对每个分区，用跨切面 grep（全仓搜 `@RestController`/`@router.post` 等）的总数与各分片之和比对——不一致即有漏项或重复，必须定位补齐。
4. 合并后的全局基线即覆盖率核对的"应该有的总数"。

## 归类与覆盖

合并基线后，归类（步骤 3–7）可继续分区并行（每子代理把自己分区的入口归类为业务功能），或由主代理统一归类。无论哪种，最终覆盖率核对以**全局合并基线**为准：枚举总数 / 已归档 / 排除 / 待确认必须 100%。大型项目建议把分片清单与合并基线留存为 `docs/project-outline-coverage.md`（可选），便于审计每个枚举项的去向。

## 子代理边界：拆什么、不拆什么

子代理只承担**可分、低一致性要求**的工作；**需要全局视角的工作留在主代理**：

| 阶段 | 可否拆给子代理 | 说明 |
|---|---|---|
| 枚举（步骤 2） | ✅ 拆 | 机械、按分区穷举，互不依赖 |
| 每模块取证/分类草稿 | ✅ 可拆 | 子代理产本分区「功能/实体/流程」草稿，标明来源 |
| 目录规划（大纲骨架） | ❌ 不拆 | 需纵观全仓定业务子域边界，拆了会割裂功能 |
| 跨模块边/数据流 | ❌ 不拆 | 边天然跨分区，只有拿全局基线的主代理能追 |
| 最终成文（项目大纲正文） | ❌ 不拆 | 一致术语、跨模块流程、Mermaid、覆盖率核对都需单一视角 |

把正文写作拆给多个子代理会得到风格不一、跨模块关系缺失的拼装文档。这与 Qoder 不同：Qoder 拆的是各自独立的 wiki 长文，它仍把目录规划集中做；我们产出的是**一份连贯大纲**，更不该拆写作。主代理合并各分区草稿后统一改写为正文；正文过长时把全量明细压到 `docs/project-outline-coverage.md` 附录，而非拆写作。

## 防漏自检

- 全仓跨切面 grep 的入口总数 = 各分片入口数之和？不等则有漏/重。
- 每个顶层模块是否都有分片覆盖？空分片要确认是真无入口还是漏扫。
- 入口数与 §5 功能清单条目数是否对得上？对不上即有未归类项，必须补归类或标噪音排除。
