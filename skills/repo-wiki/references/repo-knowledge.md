# 阶段4：仓库级约定

仓库级提取 6 个固定跨切面类别——非模块级，是**全仓模式/约定/架构决策**。作为特殊根章节 `仓库级约定/` 融合到章节树中。

**所有分类名、文件名、正文均为中文。**

## 6 个固定类别

| 分类中文名 | 文件名 | 覆盖 |
|---|---|---|
| 构建系统 | `构建系统` | Maven/Gradle/npm/CI/CD、打包、发布 |
| 配置系统 | `配置系统` | 多环境、配置中心（Apollo）、profile |
| 依赖管理 | `依赖管理` | 版本锁定、私有仓库、依赖治理 |
| 异常处理 | `异常处理` | 统一异常、错误码、AOP、全局拦截 |
| 日志系统 | `日志系统` | 日志框架、级别、SLS/链路追踪 |
| 前端风格 | `前端风格` | UI/CSS/组件规范（纯后端仓标 low 不适用） |

## per-category 文件格式

`docs/wiki/仓库级约定/<中文分类名>.md`：

```markdown
---
kind: "repo_knowledge"
category: "构建系统"  # 中文分类名
title: "<语义标题，具体化，非类别名本身>"
scopes: ["**"]
updated_at: "<ISO8601>"
confidence: "high | medium | low"
---

# <语义标题>

## <H2 章节，自由命名>

<正文：仓库级模式、约定、架构决策、关键文件、开发者规范。>

## 核心架构
...

## 开发者规范
...
```

### frontmatter 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `kind` | ✅ | 固定 `repo_knowledge` |
| `category` | ✅ | 6 中文分类名之一 |
| `title` | ✅ | 语义标题（如"Maven 多模块聚合构建体系"），非类别名本身 |
| `scopes` | ✅ | 适用范围 glob，默认 `["**"]` |
| `updated_at` | ✅ | ISO8601 |
| `confidence` | ✅ | high/medium/low（见下） |

### confidence 判定

| confidence | 判定 |
|---|---|
| `high` | 清晰、成熟的体系，多处证据（专用文件、跨模块一致模式、文档化约定） |
| `medium` | 体系存在但非正式/部分实现（散落几文件、无专用结构） |
| `low` | 该仓库无相关代码——类别不适用 |

**必须输出 `low` 当**：调研后确认仓库不含该类别相关代码。具体例：
- 纯后端/CLI/库仓 → `前端风格` = low（无 CSS/HTML/UI 代码）
- 仅用 `fmt.Println`/`print()` 无日志框架 → `日志系统` = low
- 无依赖清单文件 → `依赖管理` = low
- 无构建脚本/CI/容器化 → `构建系统` = low

confidence=low 时，title 简短、正文 1-3 句说明**为何不适用**，**不臆造**体系。

### 正文结构（自由 H2，建议维度）

每类别正文覆盖：
1. **用什么系统/方案** — 框架、工具、模式
2. **关键文件与包** — 核心逻辑在哪
3. **架构与约定** — 如何组织、设计决策
4. **开发者应遵循的规则** — 约定、约束、模式

H2 标题自拟，不强求统一。

## 提取原则

- **仓库级而非模块级**：识别跨全仓的模式/约定/决策，不是单个模块的细节。
- **grounding**：不臆造。事实须有代码依据；无法确证的标 `(推断)`。
- **聚焦高价值**：剔除默认语言/框架约定（如"Java 用驼峰命名"）。
- 仅 2-5 个高信号文件即可判断一个类别，不穷举扫描。
