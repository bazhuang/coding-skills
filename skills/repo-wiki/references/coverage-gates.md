# 覆盖率门禁、自底向上生成、写边界

## 覆盖率门禁（核心准出条件）

**模块树中每个非噪音模块必须有对应的 `docs/wiki/<章节名>/<中文文件名>.md` 文件，且归属正确的章节目录。未达 100% 不得准出。**

这是解决"大型项目只有部分模块被文档覆盖"的硬门禁。覆盖验证流程：

1. 以阶段1的模块树（内存中）为基线，列出全部模块路径。
2. 以阶段2的章节规划（内存中）为章节分配基线，确认每个模块的章节归属。
3. 枚举 `docs/wiki/` 下所有子目录中的 `*.md`（排除 `总览.md`、`简介.md`）。
4. 逐模块核对：
   - 已归档：有对应 `<章节名>/<中文文件名>.md` ✅
   - 章节归属正确：文件所在目录与章节规划中的分配一致 ✅
   - 排除：标噪音的模块（审计基类/日志表/纯技术中间件/build 产物）须显式记录
   - 待确认：归属不清的进待确认项
5. 覆盖率 = 已归档 / (模块总数 - 排除数)。未达 100% 不得准出。

**扫描完整性自检**（防只扫了部分项目）：
- 模块枚举数 vs 已生成文件数对账（排除噪音后）
- 每顶层模块要么有文件覆盖（自身或子模块），要么显式标"无对外功能/噪音排除"

## 自底向上生成顺序

模块文件生成**自底向上**（叶子优先，父后行），章节目录先于模块文件创建：

1. **创建章节目录**：按章节规划创建所有章节子目录
2. **写 `简介.md`**：每个章节目录先写章节简介
3. **叶子模块优先生成**（无子模块）
   - 基于模块知识 + read_file 验证，产出 frontmatter + 知识维度章节 + `## 关系`
4. **父模块后生成**（有子模块）
   - `## 架构设计` 可综合子模块职责分工，但**不复制子模块正文**——引用其文件
   - `## 关系` 不列父子关系（由 总览.md 层级表达）
5. **root 模块最后写**
6. **总览.md 最后生成**：章节树总览
7. **仓库级约定 并行生成**：6 类别独立，无父子依赖

数据传递：
- 父模块生成时，可读取子模块文件的 `description`/`## 概述` 综合其职责分工
- 父模块正文引用子模块用 `[子模块显示名](相对路径)`，不复制正文

## 写边界

**所有写入仅落在 `docs/wiki/` 下。** 写守卫：运行只能写 wiki 目录，不得改动仓库其他文件。

允许写入：
- `docs/wiki/<章节名>/简介.md` — 章节简介文件
- `docs/wiki/<章节名>/<模块中文名>.md` — 模块知识文件（章节可嵌套，最多 2 层）
- `docs/wiki/总览.md` — 章节树总览
- `docs/wiki/仓库级约定/<中文分类名>.md` — 跨切面类别文件（6 个）

禁止写入：
- 仓库源代码
- 仓库根的 README / AGENTS.md / CLAUDE.md
- docs/wiki/ 之外的任何路径

读取不受限：可读源码、配置、文档以提取模块知识。

## .last-update.json（可选，为 v2 增量铺路）

```json
{
  "updatedAt": "2026-07-13T10:00:00.000Z",
  "command": "generate",
  "gitHead": "<git commit sha>",
  "model": "<model id>"
}
```

v1 全量生成时写入；v2 增量更新时作为"上次更新"基线。

## 准出门禁（完整清单）

1. **覆盖率 100%**：模块树每个非噪音模块有对应 `docs/wiki/<章节名>/<中文文件名>.md`；未达不得准出。
2. **章节归属正确**：每个模块文件所在目录与章节规划中的分配一致。
3. 文件名全中文，3-20 个汉字。
4. 每个模块文件有 frontmatter（`description`/`module_id`/`section` 必填）。
5. 每个模块文件有 `## 概述`（业务功能描述，非路径清单）+ `## 架构设计`；其余章节有内容才写、无则跳过（不留空节）。
6. `## 关系` 段（如有）三向（依赖/被依赖/相关）用相对路径链接到其他模块文件；**不含父子关系**。
7. 每个章节目录含 `简介.md`（frontmatter + 章节业务概述）。
8. 6 个仓库级约定类别文件齐全（不适用者 `confidence=low` 并说明）；`仓库级约定/简介.md` 包含概览表。
9. `总览.md` 按章节分组展示全部模块文件链接。描述聚焦业务功能。
10. **写边界**：所有写入仅落在 `docs/wiki/` 下。
11. 运行 `validate_repo_wiki.py` 通过（无 FAIL）。

## 未来扩展（v2 蓝图，本版不实现）

增量更新模式，留作 v2：

- **git-diff 触发**：`git diff <last-update gitHead>..HEAD --name-only` 获取变更文件，映射到受影响模块（按 source_files 反查），只重写受影响模块文件 + 其父 + index.md。
- **soft diff budget**：<5 源文件变更 → 最多更新 1-2 模块文件；>3 模块需深思考。
- **内容哈希 no-op**：对 docs/wiki/ 做树级 SHA-256 快照，运行前后对比，无变更则不写 `.last-update.json`，防止 CI 空转。
- **no-op 短路**：update 时若 git HEAD 未动 + 工作树无变更 → 跳过 agent 运行。
- **增量重生成**：只重写受影响模块文件 + 重新综合其父 + 刷新 index.md，非全量重跑。
