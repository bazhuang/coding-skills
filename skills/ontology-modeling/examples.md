# 本体建模 Skill 使用示例

## 示例1：合同管理系统建模

### 对话过程

**用户**：帮我建模一个合同管理系统

**助手**：好的！我将帮助你完成合同管理系统的本体论建模。让我们按照对象(Object)、行为(Behavior)、规则(Rules)三要素来进行。

首先，让我了解一下业务场景：

1. 这个合同管理系统主要管理什么类型的合同？
2. 涉及哪些主要的业务实体？
3. 核心业务流程是什么？

---

**用户**：主要是销售合同，涉及客户、合同、开票、收款这几个核心部分

**助手**：很好！让我们开始**对象层(Object Layer)**建模。

## 步骤1：识别核心对象

根据你的描述，我初步识别出以下核心对象：

### 已识别的核心对象：
1. **合同** - 具有独立生命周期的中心实体
2. **开票** - 基于合同创建的独立实体
3. **收款** - 基于开票或合同创建的独立实体

### 问题：

1. **关于"客户"**：
   - 客户在这个系统中是核心对象还是引用对象？
   - 是否需要管理客户的完整生命周期（创建、更新、删除）？
   - 还是从其他系统引用客户信息？

2. **关于关键属性**：
   - **合同**：合同号、合同金额、签订日期、生效日期、失效日期等
   - **开票**：开票金额、开票日期、发票类型等
   - **收款**：收款金额、收款日期、收款方式等
   - 还有哪些重要属性？

3. **关于状态**：
   - **合同状态**：草稿、待审批、生效、执行中、完成、已关闭？
   - **开票状态**：待开票、已开票、已作废？
   - **收款状态**：待收款、部分收款、已收款？

请先回答这些问题，我们再继续识别其他对象类型（实体对象、值对象、引用对象）。

---

**用户**：客户是引用对象，从CRM系统引用。合同状态有草稿、生效、完成、已关闭。开票和收款的状态你说的对。

**助手**：明白了！让我整理一下**对象层**的完整定义：

---

## 对象层(Object Layer)

### 1. 核心对象(Core Object)

#### 对象1：合同(Contract)

**类型**：核心对象

**关键属性**：
- contractId：String | 合同号（唯一标识）
- contractAmount：BigDecimal | 合同金额
- signDate：Date | 签订日期
- effectiveDate：Date | 生效日期
- expiryDate：Date | 失效日期
- customerId：String | 客户ID（引用客户对象）

**状态机**：
```
草稿 → 生效：审批通过
生效 → 完成：全部开票且全部收款
生效 → 已关闭：提前终止
完成 → 已关闭：归档
```

**关系**：
- 引用：客户(Customer) - 引用对象
- 包含：合同条款(ContractTerm) - 实体对象

#### 对象2：开票(Invoice)

**类型**：核心对象

**关键属性**：
- invoiceId：String | 发票号（唯一标识）
- invoiceAmount：BigDecimal | 开票金额
- invoiceDate：Date | 开票日期
- invoiceType：Enum | 发票类型（专票/普票）
- contractId：String | 关联合同ID

**状态机**：
```
待开票 → 已开票：开票成功
已开票 → 已作废：作废申请
```

**关系**：
- 关联：合同(Contract) - 核心对象
- 包含：开票明细(InvoiceItem) - 实体对象

#### 对象3：收款(Payment)

**类型**：核心对象

**关键属性**：
- paymentId：String | 收款单号（唯一标识）
- paymentAmount：BigDecimal | 收款金额
- paymentDate：Date | 收款日期
- paymentMethod：Enum | 收款方式（现金/转账/支票等）
- contractId：String | 关联合同ID
- invoiceId：String | 关联开票ID（可选）

**状态机**：
```
待收款 → 部分收款：部分金额到账
部分收款 → 已收款：全额到账
待收款 → 已收款：全额到账
```

**关系**：
- 关联：合同(Contract) - 核心对象
- 关联：开票(Invoice) - 核心对象（可选）

### 2. 实体对象(Entity Object)

#### 对象4：合同条款(ContractTerm)

**类型**：实体对象（属于合同）

**关键属性**：
- termId：String | 条款ID
- contractId：String | 所属合同ID
- termType：Enum | 条款类型（付款条件/交付条件/违约责任等）
- termContent：String | 条款内容
- termOrder：Integer | 条款序号

**关系**：
- 属于：合同(Contract)

#### 对象5：开票明细(InvoiceItem)

**类型**：实体对象（属于开票）

**关键属性**：
- itemId：String | 明细ID
- invoiceId：String | 所属开票ID
- itemDescription：String | 明细描述
- itemAmount：BigDecimal | 明细金额
- itemOrder：Integer | 明细序号

**关系**：
- 属于：开票(Invoice)

### 3. 值对象(Value Object)

#### 对象6：金额范围(AmountRange)

**类型**：值对象

**属性**：
- minAmount：BigDecimal | 最小金额
- maxAmount：BigDecimal | 最大金额

**使用场景**：合同金额的有效范围约束

#### 对象7：日期范围(DateRange)

**类型**：值对象

**属性**：
- startDate：Date | 开始日期
- endDate：Date | 结束日期

**使用场景**：合同有效期、开票期间等

### 4. 引用对象(Reference Object)

#### 对象8：客户(Customer)

**类型**：引用对象（来自CRM系统）

**关键属性**：
- customerId：String | 客户ID
- customerName：String | 客户名称
- customerType：Enum | 客户类型（个人/企业）

**特征**：
- 生命周期独立，由CRM系统管理
- 本系统只读引用，不修改
- 多处引用（合同、开票、收款）

## 步骤2：行为层(Behavior Layer)建模

现在让我为每个核心对象定义行为。我会逐一询问：

### 关于"合同"对象：

1. **创建行为 [C]**：如何创建合同？需要哪些前置条件？
2. **更新行为 [U]**：可以修改合同的哪些信息？修改有什么限制？
3. **查询行为 [Q]**：需要支持哪些查询场景？（按合同号查询、按客户查询、按日期范围查询等）
4. **删除行为 [D]**：合同可以删除吗？还是只能作废？
5. **衍生行为 [->]**：基于合同可以创建哪些对象？（开票、收款等）

请先描述合同的主要行为，然后我们继续其他对象。

## 最终输出示例

完整的建模文档将包含：

```markdown
# 销售合同管理系统 本体建模文档

## 1. 对象层(Object Layer)

### 1.1 核心对象
[详细定义合同、开票、收款三个核心对象]

### 1.2 实体对象
[详细定义合同条款、开票明细等实体对象]

### 1.3 值对象
[详细定义金额范围、日期范围等值对象]

### 1.4 引用对象
[详细定义客户等引用对象]

## 2. 行为层(Behavior Layer)

### 2.1 合同的行为
- 创建合同 [C]
- 审批合同 [U]
- 修改合同 [U]
- 查询合同 [Q]
- 作废合同 [D]
- 创建开票 [->]

### 2.2 开票的行为
- 创建开票 [C]
- 修改开票 [U]
- 作废开票 [D]
- 查询开票 [Q]

### 2.3 收款的行为
- 创建收款 [C]
- 确认收款 [U]
- 查询收款 [Q]

## 3. 规则层(Rules Layer)

### 3.1 对象不变式
- 合同.合同金额 > 0
- 开票.开票金额 > 0
- 开票.开票金额 <= 关联合同.剩余未开票金额

### 3.2 前置条件
- 创建开票.前置：关联合同必须存在且状态=生效
- 确认收款.前置：收款金额 > 0

### 3.3 后置条件
- 创建合同.后置：合同状态 = 草稿
- 审批通过.后置：合同状态 = 生效

### 3.4 关系约束
- 开票.合同ID 必须存在于 合同表
- 收款.合同ID 必须存在于 合同表
- 收款.开票ID 如不为空，必须存在于 开票表

### 3.5 业务规则
- 开票规则：累计开票金额不得超过合同总金额
- 收款规则：收款可以按合同收款，也可以按开票收款
- 状态转换规则：只有生效状态的合同才能创建开票

## 4. 对象关系图

```
客户(引用) ──引用──> 合同(核心)
                        │
                        ├──包含──> 合同条款(实体)
                        │
                        ├──关联──> 开票(核心)
                        │            ├──包含──> 开票明细(实体)
                        │            │
                        │            └─关联──> 收款(核心)
                        │
                        └──关联──> 收款(核心)
```

## 5. 业务流程

### 主要流程：合同签订与收款

```
创建合同(草稿)
  → 审批合同
    → 审批通过(合同状态=生效)
      → 创建开票(开票状态=已开票)
        → 创建收款(收款状态=待收款)
          → 确认收款(收款状态=已收款)
            → 判断：已全部开票且全部收款？
              → 是：合同状态=完成
                → 合同归档(合同状态=已关闭)
```
```

## 使用建议

1. **按照流程逐步进行**：不要跳过任何步骤
2. **充分讨论每个对象**：确保理解准确
3. **验证核心原则**：检查是否符合三要素原则
4. **迭代优化**：建模过程中可以反复修改完善
5. **生成完整文档**：最终输出标准格式的建模文档

这个skill将帮助你系统化地完成任何业务领域的本体建模工作！
